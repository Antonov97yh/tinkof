# PageRank на внешней памяти

Вычисление **PageRank** для ориентированного невзвешенного графа, который **не помещается в оперативную память** одного узла. Решение использует внешнюю сортировку и параллельную обработку чанков. Память, необходимая программе, регулируется параметром размера чанка и не зависит от размера графа.

## Выбор метрики

**PageRank** – итеративная мера «важности» вершин, устойчивая к гипер-узлам (вершинам с огромной степенью). Алгоритм сводится к повторяющемуся умножению разреженной матрицы на вектор, что естественно ложится на внешнюю память: достаточно хранить только список рёбер и два вектора рангов.

## Возможные подходы (рассмотренные)

1. **Внешняя сортировка + агрегация потоком** (реализован). Рёбра обрабатываются параллельными чанками, вклады `ранг/степень` сортируются и сливаются с суммированием.
2. **SQLite** – граф загружается в БД, итерации выполняются групповыми запросами. Проще в коде, но хуже контроль памяти и параллелизма.
3. **Блочный CSR** – граф предварительно конвертируется в сжатое строчное представление на диске. Самый быстрый доступ, но требует сложной предобработки.

Реализован первый вариант – он прозрачен, эффективно утилизирует CPU и гарантирует фиксированный объем ОЗУ.

## Как это работает

- Граф (`edges.csv`) читается кусками фиксированного размера (`--chunk-mb`).
- Исходящие степени и ранги хранятся в **memory‑mapped** файлах на диске (numpy memmap). Физический расход RAM минимален.
- Каждая итерация PageRank:
  1. Параллельно вычисляются вклады `(to, rank[from] / outdeg[from])` для каждого чанка рёбер.
  2. Вклады внутри чанка сортируются и записываются во временный файл.
  3. Все временные файлы сливаются внешней сортировкой с суммированием одинаковых `to`.
  4. Новый ранг = `(1-d)/N + d * dangling/N + d * сумма_вкладов`.
- Сравнение L1‑нормы разности рангов для остановки также выполняется параллельно по блокам.
